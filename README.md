# Hirrd (Get Placed) - Modern Full-Stack Job Portal

A premium, full-featured Job Portal application built using **React (Vite)**, **Tailwind CSS**, **Supabase**, and **Clerk**. Hirrd provides a seamless, secure, and beautiful platform connecting top recruiters with talented candidates.

![Hirrd Landing Page Preview](https://github.com/user-attachments/assets/1da23b25-1f29-4402-be74-03685d9b732d)

---

## 🚀 Features

### For Job Seekers 🎓
- **Smart Job Search**: Filter and search through thousands of listings by location, company name, and keyword.
- **Easy Applications**: Apply to jobs directly with resumes (securely uploaded and hosted on Supabase Storage).
- **Saved Jobs**: Bookmarks / Save jobs to view and apply later.
- **Onboarding Workflow**: Simple role selection screen on first sign-in.

### For Recruiters 💼
- **Add Companies**: Register your company with custom logos.
- **Post Jobs**: Rich-text markdown editor to describe job responsibilities and requirements.
- **Manage Openings**: Toggle hiring status (Open/Closed) in real-time.
- **Track Candidates**: View applicants' profiles, experience level, custom skills, and download resumes.

---

## 🛠️ Technology Stack

- **Frontend**: React.js (Vite), React Router v6, Tailwind CSS, Shadcn UI
- **Authentication**: Clerk (with Google OAuth and Passwordless options)
- **Database & Storage**: Supabase (PostgreSQL database & Storage buckets)
- **Forms & Validation**: React Hook Form, Zod
- **Rich Text Editor**: `@uiw/react-md-editor`

## ⚙️ Initial Setup & Installation

### 1. Clone the repository
```bash
git clone <your-repo-link>
cd job-portal-master
```

### 2. Install Dependencies
```bash
npm install
```

### 3. Setup Supabase Database
Go to your **[Supabase Dashboard](https://supabase.com)** > **SQL Editor** > **New Query**, paste the script below, and click **Run**:

```sql
-- 1. Create Companies Table
CREATE TABLE companies (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL,
  logo_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Create Jobs Table
CREATE TABLE jobs (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  location TEXT,
  requirements TEXT,
  company_id BIGINT REFERENCES companies(id) ON DELETE CASCADE,
  recruiter_id TEXT NOT NULL, -- Clerk User ID
  "isOpen" BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. Create Applications Table
CREATE TABLE applications (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  job_id BIGINT REFERENCES jobs(id) ON DELETE CASCADE,
  candidate_id TEXT NOT NULL, -- Clerk User ID
  status TEXT DEFAULT 'applied',
  resume TEXT NOT NULL,
  skills TEXT,
  experience INTEGER,
  education TEXT,
  name TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 4. Create Saved Jobs Table
CREATE TABLE saved_jobs (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  job_id BIGINT REFERENCES jobs(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL, -- Clerk User ID
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (job_id, user_id)
);

-- Disable Row Level Security (RLS) for Development simplicity
ALTER TABLE companies DISABLE ROW LEVEL SECURITY;
ALTER TABLE jobs DISABLE ROW LEVEL SECURITY;
ALTER TABLE applications DISABLE ROW LEVEL SECURITY;
ALTER TABLE saved_jobs DISABLE ROW LEVEL SECURITY;
```

### 4. Setup Supabase Storage
1. Go to **Storage** on the Supabase Sidebar.
2. Create **two new public buckets**:
   - `company-logo` (for company logos)
   - `resumes` (for candidate resumes)
3. Open the **SQL Editor** and run these commands to set up permissions for uploading and reading files:
```sql
-- Select Policies (Read Access)
CREATE POLICY "Allow public read of company-logo" ON storage.objects FOR SELECT USING (bucket_id = 'company-logo');
CREATE POLICY "Allow public read of resumes" ON storage.objects FOR SELECT USING (bucket_id = 'resumes');

-- Insert Policies (Write Access)
CREATE POLICY "Allow public insert of company-logo" ON storage.objects FOR INSERT WITH CHECK (bucket_id = 'company-logo');
CREATE POLICY "Allow public insert of resumes" ON storage.objects FOR INSERT WITH CHECK (bucket_id = 'resumes');
```

### 5. Setup Clerk Authentication & Supabase JWT Template
To authorize secure requests from Clerk to Supabase, we need a Custom JWT Template:
1. Go to your **[Clerk Dashboard](https://dashboard.clerk.com/)** > **Configure** > **JWT Templates**.
2. Click **New Template** and select **Supabase**.
3. Go back to your **Supabase Dashboard** > **Project Settings** > **API**.
4. Under **JWT Settings**, copy your **JWT Secret** (make sure it's the secret, not the public key).
5. In your Clerk template configuration:
   - Keep the template name exactly as **`supabase`**.
   - Paste your Supabase JWT Secret into the **Signing Key** field.
   - Use the **HS256** algorithm.
6. Click **Save**.

### 6. Configure Environment Variables
Create a `.env` file in the root of the project and add the following keys:

```env
VITE_SUPABASE_URL=your_supabase_project_url
VITE_SUPABASE_ANON_KEY=your_supabase_anon_public_key
VITE_CLERK_PUBLISHABLE_KEY=your_clerk_publishable_key
```

## 🏃 Running the Application

Start the local development server:
```bash
npm run dev
```

The application will launch locally at `http://localhost:5173/` (or another port specified in the console).

## ☁️ Deployment

### Live Deployment on Vercel
This project includes a pre-configured `vercel.json` file which routes all paths back to the React SPA frontend to avoid `404 Not Found` errors when users refresh deep pages.

1. Push your repository to **GitHub**.
2. Go to **[Vercel](https://vercel.com)**, import your project repository, and add the three environment variables from your `.env` file under project settings.
3. Click **Deploy**.
4. Once deployed, copy your live site's URL and add it to the **Paths/Redirect URLs** settings inside your Clerk Dashboard to allow production-grade sign-ins.
